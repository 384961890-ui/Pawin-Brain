# Pawin Brain v8.3 Codex Host Design

## Goal

Turn the final public Brain v8.3 repository into one host hub containing the
Claude Code, Codex, and ZCode editions without importing any private v9 code or
personal data.

## Product boundary

- Public capability ceiling: Brain v8.3 at commit
  `4ba244f27482025cf677d513e244df44db3ab563`.
- Claude Code remains the canonical v8.3 implementation at the repository root.
- Codex receives a native plugin adapter with equivalent hook coverage.
- ZCode remains available through the existing adapter.
- Runtime code may be copied into a plugin bundle; identities, memories,
  lessons, state, diaries, credentials, transcripts, and machine paths may not.

## Repository layout

```text
Pawin-Brain/
├── scripts/, v2/ ... v6/, memory-spec/, qmd-engine/   # Claude v8.3 source
├── zcode-shim/                                        # existing ZCode adapter
├── plugins/pawin-brain/
│   ├── .codex-plugin/plugin.json
│   ├── hooks/codex-hooks.json
│   ├── scripts/codex-hook-router.js
│   ├── scripts/bootstrap-runtime.js
│   └── runtime/                                       # generated public v8.3 runtime
├── scripts/build-codex-runtime.js
├── tests/codex/
└── .agents/plugins/marketplace.json
```

## Runtime and data

The plugin cache is immutable and versioned. Brain's existing v8.3 scripts use
`~/.claude-brain` as their working root, so the Codex adapter reconciles a
strict allowlist of public runtime files from the bundled plugin into that
directory.

The reconciler may overwrite only versioned runtime files. It must never
overwrite mutable or personal paths such as:

- `IDENTITY.md`, `STATE.md`, `config.json`
- `lessons/`, `state/`, `memory/`, `diary/`
- QMD indexes, ingested documents, loop worklogs, transcripts, or logs

Missing first-run files are created from generic public templates only.

## Hook parity

| Brain behavior | Claude Code | Codex |
|---|---|---|
| Context, state, lessons, temporal memory, intent recall | `UserPromptSubmit` | `UserPromptSubmit` |
| v8 behavior and efficacy telemetry | `PostToolUse`, `PostToolUseFailure` | `PostToolUse`（从 `tool_response` 识别失败并转成 v8 内部失败信号） |
| v6 code smell feedback | `PostToolUse` | `PostToolUse` |
| Honest-loop audit and finish-the-work | `Stop` | `Stop` |
| Think-loop stuck detection | `Stop` | `Stop` |
| Lesson capture and state update | `Stop` | `Stop` |
| Structured memory and QMD | host-independent files/services | same files/services |
| Multimodal ingest | manual CLI | same manual CLI |

The router accepts both snake_case and camelCase Codex payload fields, fails
open, caps subprocess time, and never emits malformed hook JSON.

## Installation

```bash
codex plugin marketplace add 384961890-ui/Pawin-Brain --ref main
codex plugin add pawin-brain@pawin-brain
```

The first hook invocation performs an idempotent bootstrap. A doctor command
checks Node, plugin files, Brain runtime, mutable data, hook coverage, and QMD
configuration without exposing file content.

## Release safety

- A build manifest and hash test prove the Codex runtime was generated only
  from the public v8.3 allowlist.
- Secret and identity scans cover tracked additions and generated runtime.
- Unit tests use temporary homes and fixture transcripts.
- Existing Claude and ZCode behavior is regression-tested.
- The public page and all repository links switch to `Pawin-Brain`.
