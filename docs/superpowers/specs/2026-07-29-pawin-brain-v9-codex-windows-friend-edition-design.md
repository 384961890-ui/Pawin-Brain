# Pawin-Brain v9 Codex Windows 朋友版设计规格

## 目标

做一个给已安装 Codex 和 Node.js 的 Windows 用户直接使用的压缩包。

它要保留公开 v8.3 的 Codex 能力，并带上选定的 v9 可靠性能力；包内代码、生成物和说明里，不能出现开发者的个人信息、密钥、用户专属路径、真实记忆、日志、身份设定或历史状态。

## 交付边界

朋友版从干净的公开 Pawin-Brain v8.3 开始制作。最终 ZIP 只包含：

- Codex 插件与 Hook 路由器；
- 可移植的 v9 通用运行模块；
- 空白的结构化记忆模板；
- 给 Codex agent 直接执行的结构化记忆 SOP；
- PowerShell 安装、卸载、验证和打包脚本；
- 公开 README、许可证、测试和机器可读的发布清单。

它不包含个人记忆、教训、状态、会话数据、日志、本地词表、备份、内部审计文档、私有插件市场信息和 macOS/Linux 专用安装器。

## 结构

现有公开版的 `plugins/pawin-brain/` 继续作为 Codex 适配层。新增的可移植运行模块只负责通用 v9 能力：配置检查、记忆新鲜度检查、卡死循环打断和可靠性探针。

所有可变数据目录都从环境变量 `PAWIN_BRAIN_HOME` 获取。用户不设置时，安装器在运行时从 Windows 的 `LOCALAPPDATA` 推导默认位置，并且只把实际结果写进用户自己的本地配置。压缩包源码里不出现展开后的用户名路径，也不出现任何电脑专属绝对路径。插件位置从安装脚本所在目录发现，不写死。

## 给 agent 的结构化记忆 SOP

朋友版保留公开 v8.3 的 `memory-spec/`，再补一份适合 Windows/Codex agent 直接执行的简明 SOP：

1. 建三层树：入口 `MEMORY.md`、分类 `INDEX.md`、每条事实一个叶子文件。
2. 每个受管理的叶子文件都用 frontmatter、`当前结论` 和只追加的 `历史` 三段。
3. 记忆分为用户、反馈、项目、合作方、参考资料、教训六类。
4. 检索先用字面搜索；关键词不明确时才上语义检索。
5. 相关事实用 `[[链接]]` 连起来，读取时只扩展一跳。
6. 每次写入先过格式守卫；索引自动区块要刷新；定期看园丁巡检报告。
7. 密钥和原始对话记录不进入结构化记忆树。

SOP 只用虚构例子和环境变量，不会复制任何真实记忆条目。

## 严格脱敏规则

构建采取默认拒绝：发布白名单只选择公开 v8.3 文件和经过改写的 v9 模块。打 ZIP 前，脚本必须拦截：

- 私有或运行时目录：`state`、`lessons`、会话记录、日志、备份、本地配置；
- 密钥和令牌；
- POSIX 或 Windows 的用户专属绝对路径；
- 只在构建机读取、绝不打包的私密词表所命中的内容；
- 不在发布清单里的意外文件。

允许使用通用的运行时路径发现，例如 `process.env`、PowerShell 已知目录和脚本相对路径；它们不携带身份，也是 Windows 安装必需的能力。

## 验收方式

全程不触碰开发者现有 Brain 安装，验证按以下顺序执行：

1. 跑可移植运行模块和 Codex 插件的 Node 单元测试。
2. 在全新临时目录解压 ZIP。
3. 指向一次性 `PAWIN_BRAIN_HOME`，运行 PowerShell 验证器。
4. 确认安装和卸载脚本可重复执行，并且只影响这份一次性测试配置。
5. 扫描解压后的全部文本文件：密钥、私密词、`/Users/`、`C:\\Users\\用户名`、`~/.claude-brain` 和已知私有产品名称必须为零。
6. 确认发布清单与 ZIP 内容完全一致，并确认 SOP 和模板能初始化一棵空白记忆树。

只有全部测试、全包扫描、干净目录安装和清单检查都通过，朋友版才算完成。交付内容是 ZIP、校验和与简短的人类安装说明。

## 不做的事

- 不和私有 v9 仓库同步。
- 不迁移任何已有个人记忆。
- 不打包 Node.js 或 Codex。
- 不推送 GitHub，也不改公开稳定版 v8.3。
